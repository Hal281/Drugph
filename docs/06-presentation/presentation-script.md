### คนที่ 1: เปิดตัว, ปัญหาจริง, MoSCoW & กฎเหล็ก 5 ข้อ (`00:00 – 02:15`)

> "สวัสดีครับ/ค่ะ อาจารย์และคณะกรรมการทุกท่าน พวกเราทีม `[ชื่อทีม]` วันนี้ขออนุญาตนำเสนอโปรเจกต์ **Drugph** — ระบบช่วยคำนวณขนาดยาและตรวจสอบความปลอดภัยทางคลินิกแบบ **Deterministic** สำหรับแพทย์และเภสัชกรครับ
>
> ต้องออกตัวให้ชัดเจนตั้งแต่ต้นตามมาตรฐานความปลอดภัยครับว่า ปัจจุบันระบบนี้ยังอยู่ในสถานะ **Educational SaMD Prototype** เพื่อการศึกษาและทดสอบทางวิศวกรรมซอฟต์แวร์ ยังไม่ใช่เครื่องมือแพทย์ที่ผ่านการรับรองสำหรับใช้กับผู้ป่วยจริง แต่ถูกออกแบบโครงสร้างทุกอย่างตามมาตรฐาน Clinical Decision Support ครับ
>
> จุดเริ่มต้นของ Drugph มาจากปัญหาจริงในหอผู้ป่วยวิกฤตหรือ ICU ครับ เวลารักษาผู้ป่วยหนัก แพทย์และเภสัชกรต้องสั่งยาที่มีช่วงการรักษาแคบ เช่น ยาปฏิชีวนะอย่าง Vancomycin หรือ Gentamicin ซึ่งคำนวณแบบ Fixed Dose ไม่ได้ ต้องปรับตามน้ำหนัก ส่วนสูง อายุ และค่าการทำงานของไต
>
> พอเราไล่ Root Cause ด้วย **5 Whys** เราพบ 3 ปัญหาหลักครับ:
> 1. เภสัชกรต้องกดเครื่องคิดเลขซ้อนสูตรถึง 3–4 ชั้น ทั้งค่า CrCl, น้ำหนักอุดมคติ IBW และน้ำหนักปรับปรุงในคนอ้วน AdjBW ภายใต้เวลาเร่งด่วน
> 2. **ปัญหา Boundary Gap:** ตารางปรับยาในตำราเขียนช่วงไตเป็นจำนวนเต็ม เช่น `10–25` และ `26–50 mL/min` แต่ผลแล็บคนไข้จริงมีทศนิยม เช่น `25.5` ทำให้คนไข้หลุดช่องว่างและเสี่ยงได้รับยาเต็มขนาดโดยไม่รู้ตัว
> 3. ระบบเวชระเบียน HIS เดิมในหลายโรงพยาบาลยังไม่มีเครื่องคำนวณเชิงลึก ส่วนเว็บคำนวณต่างประเทศก็ต้องต่อเน็ตตลอดและเสี่ยงต่อ PDPA
>
> เราได้สัมภาษณ์ผู้ใช้จริง 3 กลุ่มใน Gate 1 ทั้ง **เภสัชกรคลินิก ICU**, **พยาบาลวิชาชีพ**, และ **นักศึกษาบริบาลเภสัชกรรม** ทุกคนยืนยันตรงกันว่า ต้องการระบบที่เตือนทันทีเมื่อสั่งยาขับออกทางไตแต่ลืมกรอกค่า SCr, ไม่สมมติปริมาตรน้ำเกลือ IV มั่ว, และคำนวณ Vancomycin TDM เป้าหมาย **AUC₂₄** ตามแนวทาง ASHP 2020 ครับ
>
> จากปัญหาทั้งหมด เราแปลงเป็น Requirement ตามหลัก MoSCoW โดยมี **Must Have** คือ FR-01 ถึง FR-04 (คำนวณไต, น้ำหนัก, ปรับโดสปิดช่องว่างทศนิยม, และตรวจจับความปลอดภัย) และ **Should Have** คือ FR-05 (TDM AUC₂₄)
>
> และเพื่อคุมคุณภาพระดับซอฟต์แวร์ทางการแพทย์ เราตั้ง **กฎเหล็ก 5 ข้อ (Ironclad Rules)** บังคับใช้ทั้งทีมครับ:
> 1. **Zero-Error Calculation:** สูตรคำนวณทุกตัวต้องเป็น Pure Deterministic Function **ห้ามใช้ AI/LLM มาคำนวณโดสยาเด็ดขาด**
> 2. **Strict Evidence-Based:** ตัวเลขทุกตัวต้องอ้างอิงจากตำรามาตรฐาน 7 แหล่ง เช่น Sanford Guide 2024 และ Lexicomp เท่านั้น
> 3. **Therapeutic Duplication:** ต้องตรวจจับการจ่ายยาซ้ำซ้อนและยาคู่ห้ามใช้
> 4. **Real DDI & Allergy:** ตรวจจับยาตีกันตามกลไกเภสัชวิทยาจริง
> 5. **Non-Blocking Overdose Policy:** ห้ามล็อกหน้าจอหรือซ่อนตัวเลขโดสยาเวลาเกิด Overdose เผื่อแพทย์ใช้ช่วยชีวิตคนไข้ฉุกเฉิน แต่ต้องขึ้นแถบเตือนสีแดงให้เห็นชัดเจน
>
> ต่อไปขอเชิญ `[ชื่อคนที่ 2]` อธิบายว่ากฎเหล็กและ Requirement เหล่านี้ ถูกร้อยเรียงลงในสถาปัตยกรรมอย่างไรผ่าน Golden Thread ครับ"

### คนที่ 2: The Golden Thread, 3-Tier Architecture & ADRs (`02:15 – 04:30`)

> "ขอบคุณครับ/ค่ะ ในมุมมอง Software Engineering หัวใจสำคัญของโปรเจกต์เราคือ **The Golden Thread** หรือเส้นด้ายที่ร้อยเชื่อมตั้งแต่ **Problem → Requirement → Design → Feature → Automated Test** โดยไม่ขาดตอนครับ
>
> ยกตัวอย่างเส้นเรื่องที่ 1 ครับ:
> - **ปัญหา:** ผู้ป่วยโรคอ้วนได้รับยา Aminoglycosides เกินขนาดจนไตวาย
> - **Requirement (FR-02):** ระบบต้องสลับใช้น้ำหนักปรับปรุง AdjBW เมื่อผู้ป่วยอ้วนตั้งแต่ 120% ของ IBW ขึ้นไป
> - **Design:** เราออกแบบคลาส `WeightBasedCalculator` และ `RenalCalculator` ใน Logic Layer
> - **Feature:** เมื่อกรอกน้ำหนัก 120 kg สูง 170 cm ระบบสลับไปใช้ `AdjBW 87.56 kg` คำนวณ Gentamicin ได้ `437.81 mg` แทนที่จะเป็น `600 mg`
> - **Test:** เรามีไฟล์ `cockcroft_gault_renal_dosing_test.dart` ยืนยันค่าคณิตศาสตร์ตรงเป๊ะ 100%
>
> อีกตัวอย่างคือ **ปัญหา CrCl ทศนิยม 25.5 หลุดช่วง** เราก็ปิดช่องโหว่ด้วยช่วงค่าไตแบบต่อเนื่องใน `RenalAdjustment` และมี Unit Test ยืนยันว่า `25.5` ตกเข้าช่วงปรับยาทันที ทุก Requirement มีโค้ดและ Test รองรับครบทั้งหมดครับ
>
> ในด้านสถาปัตยกรรม เราแบ่งโค้ดออกเป็น **3-Tier Clean Architecture** เพื่อให้เกิด High Cohesion และ Low Coupling ครับ:
> 1. **Layer ล่างสุด — Data Layer (`lib/data/`):** เก็บฐานข้อมูลยาทั้งหมด **119 รายการยาหลัก** และ **4 รายการยาเฉพาะทาง** พร้อม `DrugSearchEngine` ที่ค้นหาได้ไวระดับเสี้ยววินาที และ `PrescriptionCart`
> 2. **Layer กลาง — Domain / Logic Layer (`lib/core/`):** เป็น Pure Dart Engine 100% ไม่มีโค้ด Flutter UI และไม่เรียก Network เลย ฝั่งคำนวณทั้งหมดตั้งแต่ `PharmacistCalculator`, `TdmCalculator`, จนถึง `PkSimulationEngine` อยู่ในชั้นนี้ ทำให้ง่ายต่อการทำ Unit Test
> 3. **Layer บนสุด — Presentation Layer (`lib/ui/`):** ใช้ Material 3 บนหลัก 8-pt Grid และปุ่มกดขนาด ≥ 48 dp ตามมาตรฐาน WCAG AAA โดย UI มีหน้าที่รับ Input และแสดงผลตาม DTO เท่านั้น ห้ามแอบคำนวณเอง
>
> จากสถาปัตยกรรมนี้ นำมาสู่การตัดสินใจสำคัญหรือ **ADR-01**: เราเลือกพัฒนาแบบ **Client-Side Deterministic 100%** ไม่ยิง API ออกนอกเครื่อง ทำให้ได้ผลลัพธ์ในระดับ `< 100 ms`, ทำงาน **Offline 100%** ในห้องผ่าตัดหรือ ICU ที่อับสัญญาณ, และข้อมูลผู้ป่วยไม่หลุดออกนอกเครื่องตามหลัก PDPA ครับ
>
> นอกจากการคำนวณที่แม่นยำแล้ว เกราะป้องกันด้านความปลอดภัยของคนไข้ทำงานอย่างไร ขอเชิญ `[ชื่อคนที่ 3]` ในส่วนถัดไปครับ"

### คนที่ 3: Clinical Safety Guardrails (`04:30 – 06:00`)

> "ขอบคุณครับ/ค่ะ ในฝั่งความปลอดภัยทางคลินิก ทีมเราออกแบบระบบป้องกันไว้ 3 ด่านสำคัญใน `lib/core/validators/` และ `lib/core/models/` ครับ
>
> **ด่านที่ 1: Therapeutic Duplication Prevention (`TherapeuticDuplicationService`)**
> นอกจากตรวจจับการสั่งยาตัวเดิมซ้ำแล้ว เรายังตรวจจับ **5 กลุ่มยาคู่ห้ามใช้เด็ดขาด** ได้แก่:
> 1. **Dual NSAIDs** (เช่น Ibuprofen + Naproxen) เสี่ยงเลือดออกทางเดินอาหารและไตวาย
> 2. **Dual RAS Blockade** (ACEI + ARB เช่น Enalapril + Losartan) เสี่ยงโพแทสเซียมสูงวิกฤต
> 3. **Dual Oral Anticoagulants** (Warfarin + DOAC หรือ DOAC ซ้ำกัน) เสี่ยงเลือดออกถึงชีวิต
> 4. **Dual Statins** เสี่ยงกล้ามเนื้อลายสลาย
> 5. **Dual Potassium-Sparing Diuretics** เสี่ยงหัวใจหยุดเต้น
>
> **ด่านที่ 2: DDI และ Allergy Cross-Reactivity**
> ระบบจับคู่ชื่อยาได้ทั้งชื่อสามัญ ชื่อการค้าภาษาไทย (เช่น พิมพ์แพ้ *พอนสแตน* หรือ *Voltaren* ก็จะรู้ว่าเชื่อมโยงกับกลุ่ม NSAIDs) รวมถึงเตือนการแพ้ข้ามกลุ่มใน Beta-lactam และตรวจจับยาตีกันระดับ Major เช่น `Vancomycin + Gentamicin` พร้อมระบุกลไกและแนวทางจัดการ
>
> **ด่านที่ 3: กฎเหล็กข้อที่ 5 — Non-Blocking Overdose Policy (`DEC-OVERDOSE-001`)**
> จากโจทย์ของแพทย์ฉุกเฉิน ถ้าซอฟต์แวร์ไปล็อกหน้าจอไม่ให้เห็นโดสยาเวลาคำนวณเกิน Max Limit อาจทำให้ช่วยชีวิตคนไข้ในห้อง ER ไม่ทัน ดังนั้น `SafetyAlertBanner` ของเราจะขึ้นแบนเนอร์เตือนสีแดงเด่นชัด **แต่ยังแสดงตัวเลขขนาดยาจริงให้แพทย์และเภสัชกรเห็นและตัดสินใจได้ทันที** ครับ
>
> เพื่อให้เห็นภาพการทำงานจริงทั้งหมด ขอเชิญ `[ชื่อคนที่ 4]` สาธิต Live Demo กับเคสผู้ป่วยจริงบนหน้าจอเลยครับ"

- *(จังหวะที่ 2 — Gentamicin: ค้นหา `Gentamicin` → คลิกเลือก → กดคำนวณ)*
> "สมมติผู้ป่วยติดเชื้อรุนแรงและแพทย์พิจารณาให้ **Gentamicin** ครับ ผมพิมพ์ค้นหา `Gentamicin` คลิกเลือกแล้วกดคำนวณ... ดูผลลัพธ์ทางด้านขวาครับ:
> 1. ระบบคำนวณ **Devine IBW ได้ `65.94 kg`** และตรวจพบว่าน้ำหนัก 120 kg เกินเกณฑ์ 120% จึงสลับไปใช้ **Adjusted Body Weight (AdjBW) = `87.56 kg`** อัตโนมัติ ทำให้ขนาดยาที่ได้คือ **`437.81 mg`** ช่วยลดความเสี่ยงพิษต่อไตจาก `600 mg` ถ้าใช้ TBW ตรงๆ
> 2. และในสมการ Cockcroft-Gault ระบบเลือกใช้ AdjBW คำนวณได้ **`CrCl = 54.05 mL/min`** (แทนที่จะหลอกตาเป็น `74.07` ถ้าใช้น้ำหนัก 120 kg) จึง **ปรับความถี่จาก q24h เป็น `q36h` ให้อัตโนมัติ** พร้อมแสดงการ์ด **IV Diluent Compatibility**"

- *(จังหวะที่ 3 — Vancomycin & Rule 5: กด `เพิ่มลงตะกร้ายา` ให้ Gentamicin → ค้นหา `Vancomycin` → คลิกเลือก → กดคำนวณ)*
