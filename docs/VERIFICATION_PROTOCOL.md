# VERIFICATION_PROTOCOL.md — ระเบียบปฏิบัติการตรวจรับรองข้อมูลและสูตรคำนวณยาทางคลินิก
> **เอกสารควบคุมคุณภาพ (Quality & Clinical Governance Protocol) สำหรับระบบ Drugph**  
> **บังคับใช้สำหรับ: แพทย์, เภสัชกรคลินิก, นักพัฒนาซอฟต์แวร์ และ AI Assistants ทุกคน**

---

## 1. หลักการและเหตุผล (Clinical Rationale)
Drugph ถูกออกแบบให้เป็นระบบสนับสนุนการตัดสินใจทางคลินิก (Clinical Decision Support System - CDSS) และจัดเป็นเครื่องมือแพทย์ประเภทซอฟต์แวร์ (Software as a Medical Device - SaMD)  
ตาม **กฎเหล็กข้อที่ 1 (Zero-Error Calculation Policy)** และ **กฎเหล็กข้อที่ 2 (Strict Evidence-Based Medicine)**:
* **ห้าม AI หรือผู้พัฒนาคาดเดา อนุมาน หรือแต่งข้อมูลทางการแพทย์ขึ้นมาเองโดยเด็ดขาด (Strictly No Hallucination)**
* สูตรคำนวณ โดสยา ตัวเลขการปรับยาตามไต (CrCl) และคำเตือนทุกตัว ต้องสามารถสืบย้อน (Traceability) ไปยังตำราแพทย์และเภสัชกรรมมาตรฐานได้ 100%
* ข้อมูลยาทุกตัวในระบบถือว่าเป็น **UNVERIFIED (รอยืนยัน)** จนกว่าจะได้รับการตรวจทานเทียบตำราและลงนามรับรองโดยเภสัชกรคลินิกและอาจารย์แพทย์

---

## 2. ลำดับชั้นตำรามาตรฐานที่ได้รับอนุญาต (Approved Clinical Textbooks)
ข้อมูลยา สูตรยา และการปรับโดสใน Drugph ต้องอ้างอิงจาก 7 แหล่งมาตรฐานนี้เท่านั้น:

1. **The Sanford Guide to Antimicrobial Therapy (54th Edition, 2024 / Web Edition)**  
   *ใช้เป็นเกณฑ์หลักสำหรับ: ยาปฏิชีวนะ, ยาต้านเชื้อรา, ยาต้านไวรัส, การปรับโดสตามไต (Table 10), และเป้าหมาย TDM*
2. **Lexicomp Drug Information / UpToDate**  
   *ใช้เป็นเกณฑ์หลักสำหรับ: ขนาดยาสามัญ, ปฏิกิริยาระหว่างยา (Drug Interactions), ขนาดยาสูงสุด (Dose Limits), และความปลอดภัยในสตรีมีครรภ์/ให้นมบุตร*
3. **คู่มือการปรับขนาดยาในผู้ป่วยโรคไต โดย สมาคมโรคไตแห่งประเทศไทย (The Nephrology Society of Thailand)**  
   *ใช้เป็นเกณฑ์หลักสำหรับ: ช่วงระดับ CrCl (Renal Cutoffs) และแนวทางการปรับยาในผู้ป่วยไตวายเรื้อรัง/ฟอกเลือด (Hemodialysis)*
4. **แนวทางการรักษาโรคติดเชื้อในประเทศไทย โดย สมาคมโรคติดเชื้อแห่งประเทศไทย (IDAT Guidelines)**  
   *ใช้เป็นเกณฑ์หลักสำหรับ: โรคติดเชื้อเขตร้อนและอุบัติการณ์เชื้อดื้อยาในบริบทโรงพยาบาลไทย*
5. **บัญชียาหลักแห่งชาติ (NLEM) และคู่มือการใช้ยาอย่างสมเหตุผล (RDU Thailand โดย สำนักงานคณะกรรมการอาหารและยา)**  
   *ใช้เป็นเกณฑ์หลักสำหรับ: ขนาดยาที่เหมาะสมในบริบทสาธารณสุขไทยและคำเตือนความปลอดภัยของ อย.*
6. **คู่มือการบริหารยาฉีดสำหรับพยาบาลและเภสัชกร (โรงพยาบาลรามาธิบดี และ โรงพยาบาลศิริราช)**  
   *ใช้เป็นเกณฑ์หลักสำหรับ: การเจือจางยาฉีด (IV Dilution), สารน้ำที่เข้ากันได้ (Compatibility), อัตราและเวลาในการหยดยา (Infusion Rates), และการจัดการการรั่วซึม (Extravasation Antidotes)*
7. **DiPiro's Pharmacotherapy: A Pathophysiologic Approach & Goodman & Gilman's The Pharmacological Basis of Therapeutics**  
   *ใช้เป็นเกณฑ์หลักสำหรับ: เภสัชจลนศาสตร์ (Pharmacokinetics), กลไกการออกฤทธิ์, และชีวสมมูล*

## 3. ขั้นตอนการตรวจรับรอง 5 ขั้น (5-Step Verification SOP)

```
[ขั้นตอนที่ 1]             [ขั้นตอนที่ 2]            [ขั้นตอนที่ 3]          [ขั้นตอนที่ 4]             [ขั้นตอนที่ 5]
AI / ผู้พัฒนาร่างข้อมูล  ──>  ส่งออกเอกสาร PDF  ──>  เภสัชกรคลินิกตรวจทาน ──>  อาจารย์แพทย์อนุมัติ ──>  บันทึก Provenance
(ดึงจากตำรามาตรฐาน)       (Dossier 41 หน้า)        เทียบตำราและลงนาม        ลงนามขั้นสุดท้าย         ลงใน Source Code
```

### ขั้นที่ 1: การร่างข้อมูลยา (Data Ingestion & Proposing)
- AI หรือนักพัฒนาค้นคว้าข้อมูลจากตำรามาตรฐาน 7 แหล่งข้างต้น
- จัดทำโครงสร้างข้อมูลตามโมเดล `ClinicalMonograph`:
  - `textbookName`: ชื่อตำรา
  - `editionYear`: ปีพิมพ์หรือครั้งที่พิมพ์
  - `sectionOrTable`: หน้า/ตาราง/หัวข้อที่อ้างอิง
  - `dosingGuideline`: โดสมาตรฐาน
  - `renalGuideline`: เกณฑ์การปรับยาตามไต
  - `administrationGuideline`: การบริหารยาและการเจือจาง
  - `clinicalNotes`: คำเตือนและพิษเฉียบพลัน
- ข้อมูลที่ร่างโดย AI ต้องมีสถานะเป็น `VerificationStatus.pendingReview` จนกว่าจะมีผู้ตรวจจริง

### ขั้นที่ 2: การสร้างเอกสารเพื่อการตรวจทาน (PDF Dossier Generation)
- รันคำสั่งสร้างเอกสารสรุปรายการยาทั้งหมด:
  ```powershell
  dart run tool/generate_pharmacist_dossier_pdf.dart
  ```
- ไฟล์ PDF จะถูกสร้างขึ้นที่ `review/Clinical_Verification_Dossier.pdf` (พร้อมตารางสูตรยา, เกณฑ์ไต, ขนาดยาสูงสุด, และช่องลงลายมือชื่อกำกับทุกตัวยา)

### ขั้นที่ 3: เภสัชกรคลินิกตรวจทาน (Clinical Pharmacist Review)
- เภสัชกรเปิดตำรามาตรฐานเทียบกับตารางในเอกสาร PDF
- ตรวจสอบ:
  1. ความถูกต้องของตัวเลขโดสยาและหน่วย (mg, mcg, g, mg/kg, mcg/kg/min)
  2. ความถูกต้องของตาราง CrCl และสูตรการปรับยา
  3. คำเตือนระดับวิกฤต (High-Alert / Black Box Warnings / Contraindications)
- ลงลายมือชื่อกำกับในช่องตรวจรับรอง พร้อมระบุ:
  - ชื่อ-นามสกุล
  - เลขที่ใบประกอบวิชาชีพเภสัชกรรม (ภ. XXXXX)
  - วันที่ตรวจรับรอง

### ขั้นที่ 4: อาจารย์แพทย์ตรวจอนุมัติ (Physician / PTC Approval)
- อาจารย์แพทย์ผู้เชี่ยวชาญหรือประธานคณะกรรมการเภสัชกรรมและการบำบัด (PTC) ตรวจสอบและลงนามในหน้าสุดท้ายของ Dossier
- ระบุชื่อ-นามสกุล, เลขที่ใบประกอบวิชาชีพเวชกรรม (ว. XXXXX), ตำแหน่ง และวันที่อนุมัติ

### ขั้นที่ 5: บันทึกข้อมูลการรับรองเข้าสู่ระบบ (Source Code Provenance Update)
- นำผลการตรวจรับรองมาบันทึกลงในฟิลด์ `provenance` ของตัวยานั้น ๆ ใน `lib/data/drugs/`:
  ```dart
  provenance: const Provenance(
    source: 'The Sanford Guide to Antimicrobial Therapy 2024 (54th Ed.)',
    reviewedBy: 'ภก.คลินิก ด้านโรคติดเชื้อ (BCPS)',
    reviewedAt: '2024-10-12',
    sourceDetail: 'Table 10A & 10B',
    reviewerLicense: 'ภ. 14582',
    approvedBy: 'คณะกรรมการเภสัชกรรมและการบำบัด (PTC)',
  ),
  ```
- เปลี่ยนสถานะเป็น `VerificationStatus.verified`
- เขียน Unit Test ยืนยันผลการคำนวณทุกกรณี

## 4. กฎเหล็กถาวรสำหรับ AI Assistants ในอนาคต
1. **ห้ามเปลี่ยนตัวเลขโดสยาตามอำเภอใจ:** หากไม่มีเอกสารอ้างอิงจาก 7 ตำรามาตรฐานข้างต้น ห้ามแก้ไขตัวเลขการคำนวณเด็ดขาด
2. **ห้ามลบคำเตือนความปลอดภัย:** คำเตือน Overdose, Red Man Syndrome, QT Prolongation, Serotonin Syndrome และการแพ้ยา ห้ามปิดบังหรือลบออก
3. **รักษาความสามารถในการแสดงผล Monograph:** ฟังก์ชัน `ClinicalEvidenceSheet` ในหน้าต่างคำนวณยาต้องเชื่อมต่อกับข้อมูลตำราจริงเสมอ
4. **เคารพนโยบาย Non-blocking (กฎข้อที่ 5):** แม้ตัวเลขจะเกินเกณฑ์ปลอดภัยหรือยังไม่ได้รับการรับรอง ต้องแสดงผลตัวเลขให้แพทย์เห็น พร้อมแถบเตือนสีแดงเสมอ ห้ามล็อกหน้าจอ
